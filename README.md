# Хвост и Лапы

Информационная система ветеринарной клиники: онлайн-запись питомцев на приём.

Учебная практика · 09.02.07 · Вариант 4.

---

## Возможности

- **Регистрация** владельца питомца с проверкой формата логина, ФИО, телефона, почты и пароля.
- **Авторизация** с проверкой пароля на сервере (`password_hash` / `password_verify`).
- **Профиль питомцев**: питомец добавляется один раз (кличка, вид, порода,
  дата рождения, заметка), а при записи выбирается из списка. Питомца,
  на которого есть заявки, удалить нельзя — иначе записи остались бы без питомца.
- **Личный кабинет**: список своих заявок с текущим статусом, **отмена заявки**
  в статусе «Новая» с подтверждением и отзыв после завершения приёма.
- **Панель администратора**: сводка по статусам, фильтр по статусу и услуге,
  поиск по кличке питомца или ФИО владельца, пагинация, всплывающие сообщения,
  управление статусами. Смена статуса происходит без перезагрузки страницы:
  бейдж, счётчики и список доступных переходов обновляются на месте.
- **Запись на приём** из справочников: питомец и услуга выбираются из списков,
  дата и время — нативные поля выбора. Время приёма ограничено часами работы
  клиники (09:00–20:00) и проверяется дважды: браузером (атрибуты `min`/`max`/`step`)
  и сервером (`Validator::time()` → `Schedule`).
- **Слайдер** на главной странице: 4 изображения одинакового размера,
  автосмена каждые 3 секунды, кнопки «вперёд/назад», точки, свайп на смартфоне.
  Фото слайда 4 — U.S. Air Force, public domain.
- **Анимации**: плавное появление карточек, анимация смены статуса,
  микроанимации кнопок и полей (hover / focus / ошибка), выезжающие уведомления.
  Учитывается системная настройка «уменьшить движение».
- **Адаптивный дизайн**: проверены ширины 390, 768 и 1280 px;
  таблица заявок на узком экране превращается в карточки.

## Жизненный цикл заявки

```
«Новая» ──► «Подтверждена» ──► «Приём завершён»
    │              │
    └──────────────┴──────► «Отменена»
```

Любой переход вне этой схемы отклоняется на сервере. Отзыв доступен только
при статусе «Приём завершён» и только один раз на заявку. Отменяет заявку
в статусе «Новая» и администратор, и сам владелец — из кабинета.

## Справочники предметной области

Значения хранятся в БД строчными буквами, на страницах выводятся с заглавной буквы.
Список задан один раз в `backend/config.php` и используется в трёх местах:
валидация на сервере, `CHECK`-ограничения в БД и выпадающие списки на странице записи.

| Поле        | Значения                                                                 |
|-------------|--------------------------------------------------------------------------|
| Вид животного | кошка, собака, грызун, птица, другое                                    |
| Услуга      | первичный осмотр, вакцинация, стрижка когтей, УЗИ                        |
| Часы работы | 09:00–20:00                                                               |
| Оплата      | Наличными, Картой в клинике                                               |

Вид животного указывается один раз — при добавлении питомца в профиль,
а не в каждой заявке.

## Стек

- **PHP 8.2** — серверная логика, ООП-классы
- **PostgreSQL 18** — СУБД, PDO с подготовленными запросами
- **Bootstrap 5.3** и **bootstrap-icons** — подключены локально
  (в `frontend/assets/vendor/`), интернет не нужен
- **JavaScript** — слайдер, мобильное меню, клиентская валидация,
  анимации, отправка формы смены статуса через `fetch`

## Установка

1. Включить расширение PostgreSQL в `php.ini`:
   ```ini
   extension=pdo_pgsql
   ```
2. Создать базу данных:
   ```sql
   CREATE DATABASE vetclinic ENCODING 'UTF8';
   ```
3. Загрузить структуру и данные:
   ```bash
   psql -U postgres -d vetclinic -f backend/database/dump.sql
   php backend/database/seed.php
   ```
   Скрипт `seed.php` идемпотентен: повторный запуск не создаёт дубликаты.
   Демо-данные — 9 питомцев и 8 заявок во всех статусах и по всем услугам
   (хватает на две страницы пагинации) и один отзыв.

   Если `dump.sql` уже загружался раньше и в нём появились новые ограничения,
   таблицы нужно пересоздать заново — скрипт начинается с `DROP TABLE`.
4. При необходимости поправить доступы в `backend/config.php`.
5. Открыть `index.php` в браузере (или `php -S localhost:8080 -t .`).

> В `backend/database/dump.sql` логин администратора `Admin` разрешён как исключение
> из общего правила «не менее 6 символов», потому что он задан условием задания.

## Правила безопасности, реализованные в проекте

- пароли хранятся только в виде хеша `password_hash()`;
- все SQL-запросы с пользовательскими данными выполняются через `prepare` / `execute`;
- весь пользовательский вывод экранируется через `htmlspecialchars()` (`e()`);
- проверка прав выполняется на сервере: `Auth::requireLogin()` и `Auth::requireAdmin()`;
- питомец при записи проверяется на принадлежность владельцу
  (`Pet::findForUser()`), поэтому подсунуть чужой `pet_id` нельзя;
- отмена заявки доступна только её владельцу и только из статуса «Новая»;
  чужая заявка и запись не из «Новой» отклоняются одинаковым сообщением;
- допустимость перехода статуса проверяется на сервере перед обновлением;
- возможность оставить отзыв определяется статусом заявки, а не только скрытием кнопки;
- значения из адресной строки (фильтры, поиск, номер страницы) сверяются со
  справочниками и ограничиваются по длине **до** попадания в запрос;
- символы-шаблоны `LIKE` экранируются, поэтому «%» в поиске ищется как буква;
- адрес возврата после смены статуса проверяется регулярным выражением,
  подделать его можно только ссылкой внутри панели администратора.

## Проверка перед сдачей

```powershell
Get-ChildItem -Recurse -Filter *.php -Path backend, frontend, tools, index.php |
    ForEach-Object { php -l $_.FullName }

php tools/reload_db.php         # пересоздать таблицы по dump.sql
php backend/database/seed.php   # залить демо-данные
php -S 127.0.0.1:8088 -t .      # сервер (второе окно)
php tools/smoke.php             # ~110 проверок, код возврата 0 — всё зелёное
powershell -NoProfile -ExecutionPolicy Bypass -File tools/screenshots.ps1
```

`tools/smoke.php` пересоздаёт базу, поэтому запускать его нужно на dev-копии.
