# Хвост и Лапы

Информационная система ветеринарной клиники: онлайн-запись питомцев на приём.

Учебная практика · 09.02.07 · Вариант 4.

---

## Возможности

- **Регистрация** владельца питомца с проверкой формата логина, ФИО, телефона, почты и пароля.
- **Авторизация** с проверкой пароля на сервере (`password_hash` / `password_verify`).
- **Личный кабинет**: список своих заявок с текущим статусом и возможность оставить отзыв
  после завершения приёма.
- **Панель администратора**: все заявки, сводка по статусам, фильтр, управление статусами.
- **Слайдер** на главной странице: 4 изображения, автосмена каждые 3 секунды, кнопки и точки.

## Жизненный цикл заявки

```
«Новая» ──► «Подтверждена» ──► «Приём завершён»
    │              │
    └──────────────┴──────► «Отменена»
```

Любой переход вне этой схемы отклоняется на сервере. Отзыв доступен только
при статусе «Приём завершён» и только один раз на заявку.

## Стек

- **PHP 8.2** — серверная логика, ООП-классы
- **PostgreSQL 18** — СУБД, PDO с подготовленными запросами
- **Bootstrap 5.3** — подключён локально (в `frontend/assets/vendor/`), интернет не нужен
- **JavaScript** — слайдер, мобильное меню, клиентская валидация

## Установка

1. Включить расширение PostgreSQL в `php.ini`:
   ```ini
   extension=pdo_pgsql
   ```
2. Создать базу данных:
   ```sql
   CREATE DATABASE vetclinic ENCODING 'UTF8';
   ```
3. Загрузить структуру и данные:
   ```bash
   psql -U postgres -d vetclinic -f backend/database/dump.sql
   php backend/database/seed.php
   ```
4. При необходимости поправить доступы в `backend/config.php`.
5. Открыть `index.php` в браузере.

> В `backend/database/dump.sql` логин администратора `Admin` разрешён как исключение
> из общего правила «не менее 6 символов», потому что он задан условием задания.

## Правила безопасности, реализованные в проекте

- пароли хранятся только в виде хеша `password_hash()`;
- все SQL-запросы с пользовательскими данными выполняются через `prepare` / `execute`;
- весь пользовательский вывод экранируется через `htmlspecialchars()` (`e()`);
- проверка прав выполняется на сервере: `Auth::requireLogin()` и `Auth::requireAdmin()`;
- допустимость перехода статуса проверяется на сервере перед обновлением;
- возможность оставить отзыв определяется статусом заявки, а не только скрытием кнопки.
